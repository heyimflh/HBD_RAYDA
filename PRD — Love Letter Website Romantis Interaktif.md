# PRD — Love Letter Website Romantis Interaktif

<aside>
💌

PRD ini mendefinisikan website personal berbentuk surat cinta digital yang romantis, cerah, interaktif, dan penuh memori untuk pasangan/kekasih. Fokus utamanya adalah menghadirkan pengalaman emosional seperti membuka hadiah digital: lembut, manis, estetik, personal, dan memorable.

</aside>

## 1. Ringkasan Produk

### 1.1 Nama Produk

**Love Letter Website — Romantic Digital Gift for Her**

Alternatif nama:

- **Untukmu, Selalu**
- **A Letter for My Love**
- **Our Little Universe**
- **Bunga Digital Untukmu**
- **The Day I Met You**
- **Because It’s You**
- **Love, Memories, and Us**

### 1.2 Deskripsi Singkat

Website ini adalah **surat romantis digital interaktif** yang dibuat khusus untuk pasangan/kekasih. Di dalamnya terdapat kumpulan foto, video, kata-kata manis, surat cinta, kalender tanggal awal bertemu, galeri polaroid estetik, timeline kenangan, wishlist tempat yang ingin dikunjungi bersama, digital gift seperti bunga virtual, serta section interaktif romantis yang membuat pasangan merasa dihargai, dicintai, dan spesial.

Website dirancang dalam **light mode** dengan nuansa warna cerah, hangat, lembut, feminin-romantis, dan elegan. Pengalaman pengguna dibuat seperti perjalanan emosional dari awal membuka website hingga akhir, seolah-olah pasangan sedang membuka kotak hadiah penuh cinta.

### 1.3 Tujuan Utama

Membuat website yang:

- Terasa seperti **hadiah digital personal**.
- Memiliki visual UI yang **romantis, cantik, clean, dan penuh cinta**.
- Menggabungkan foto, video, pesan, dan interaksi kecil yang menyentuh hati.
- Bisa menjadi arsip kenangan hubungan.
- Bisa dibuka di HP dengan nyaman karena kemungkinan besar pasangan akan membukanya lewat smartphone.
- Memberikan pengalaman emosional yang membuat pasangan merasa:
    - dicintai,
    - diperhatikan,
    - diingat,
    - dihargai,
    - dan disayang dengan tulus.

## 2. Latar Belakang

Hadiah romantis biasanya berbentuk surat fisik, bunga, foto cetak, scrapbook, video montage, atau hadiah barang. Namun, website personal dapat menggabungkan semua bentuk hadiah tersebut ke dalam satu pengalaman digital yang lebih interaktif dan berkesan.

Website ini bukan sekadar halaman statis, tetapi **ruang kecil digital berisi cinta dan memori**. Setiap section harus terasa seperti halaman dalam scrapbook romantis: ada pembuka yang manis, foto-foto estetik, surat cinta, timeline kenangan, kalender momen penting, playlist, wishlist tempat, dan penutup yang emosional.

Karena tujuan website adalah untuk kekasih, pendekatan desain tidak boleh terlalu formal atau kaku. UI harus lembut, visual harus hangat, animasi harus halus, dan copywriting harus personal.

## 3. Visi Produk

### 3.1 Visi

Menciptakan sebuah website romantis yang terasa seperti **surat cinta hidup**: indah dilihat, menyenangkan disentuh, penuh kejutan kecil, dan meninggalkan kesan emosional yang mendalam bagi pasangan.

### 3.2 Prinsip Pengalaman

Website harus terasa:

- **Romantic** — penuh cinta, hangat, dan personal.
- **Soft** — warna lembut, animasi pelan, tidak agresif.
- **Memorable** — setiap section punya makna.
- **Personal** — konten terasa dibuat hanya untuk pasangan.
- **Interactive** — ada interaksi kecil yang membuat pengguna merasa terlibat.
- **Aesthetic** — layout foto/video indah seperti scrapbook digital.
- **Mobile-first** — nyaman dibuka lewat HP.
- **Light & cheerful** — cerah, bersih, tidak gelap.

## 4. Target Pengguna

### 4.1 Primary User

**Pasangan/kekasih penerima website**

Karakteristik:

- Membuka website melalui link yang dikirim secara personal.
- Kemungkinan besar mengakses via smartphone.
- Mengharapkan pengalaman emosional, bukan sekadar informasi.
- Ingin merasa bahwa website dibuat khusus untuk dirinya.
- Akan melihat foto, membaca surat, menonton video, dan mengeksplorasi section interaktif.

### 4.2 Secondary User

**Pembuat website**

Karakteristik:

- Ingin memberikan hadiah romantis yang unik.
- Perlu struktur konten yang rapi.
- Ingin website terlihat profesional, indah, dan menyentuh.
- Membutuhkan kemudahan mengganti foto, video, tanggal, nama, surat, dan wishlist.

## 5. Persona Pengguna

### Persona 1 — Kekasih Penerima Hadiah

**Nama Persona:** The Loved One  

**Tujuan:** Merasakan hadiah digital yang personal dan romantis.  

**Kebutuhan:**

- Website mudah dibuka.
- Tampilan cantik dan tidak membingungkan.
- Konten terasa personal.
- Ada kejutan kecil yang membuat tersenyum.
- Bisa melihat kenangan dalam bentuk foto/video.

**Pain Point:**

- Website terlalu ramai bisa terasa norak.
- Animasi berlebihan bisa mengganggu.
- Copywriting yang terlalu umum tidak terasa personal.
- Loading foto/video yang lambat bisa merusak momen.

### Persona 2 — Pembuat Hadiah

**Nama Persona:** The Romantic Creator  

**Tujuan:** Membuat website sebagai hadiah cinta yang berkesan.  

**Kebutuhan:**

- Template konten mudah diisi.
- Section lengkap untuk berbagai jenis memori.
- Desain indah tanpa harus terlalu kompleks.
- Bisa deploy dan dibagikan dengan mudah.
- Konten dapat diperbarui di masa depan.

## 6. Problem Statement

Pembuat hadiah ingin memberikan sesuatu yang lebih personal daripada chat panjang atau hadiah biasa. Namun, membuat pengalaman romantis digital yang rapi, estetik, dan emosional membutuhkan struktur, desain, copywriting, dan fitur interaktif yang matang.

Website ini perlu menjawab tantangan:

- Bagaimana membuat website yang terasa seperti hadiah cinta, bukan sekadar portfolio foto?
- Bagaimana menyusun foto, video, surat, kalender, wishlist, dan elemen interaktif agar tidak berantakan?
- Bagaimana membuat tampilan cerah/light mode yang romantis tapi tetap modern?
- Bagaimana membuat pengalaman yang menyentuh hati tanpa terlihat berlebihan?
- Bagaimana memastikan website tetap ringan, cepat, dan nyaman di mobile?

## 7. Goals & Non-Goals

### 7.1 Goals

Website harus:

- Menampilkan surat romantis digital secara indah.
- Memiliki landing hero yang langsung menyentuh emosi.
- Menyediakan galeri foto dalam style polaroid/grid estetik.
- Menampilkan video pasangan atau video kenangan.
- Menampilkan kalender tanggal awal bertemu dan momen penting.
- Menyediakan surat cinta panjang yang bisa dibaca dengan nyaman.
- Memiliki section kata-kata manis.
- Memiliki interactive romantic section.
- Menyediakan digital gift seperti bunga virtual.
- Menampilkan wishlist tempat yang ingin dikunjungi bersama.
- Memiliki desain light mode yang cerah dan romantis.
- Responsif untuk mobile, tablet, dan desktop.
- Mudah dikustomisasi kontennya.
- Memiliki animasi lembut dan micro-interactions yang tidak mengganggu.
- Bisa dibagikan lewat link.

### 7.2 Non-Goals

Website tidak harus:

- Menjadi aplikasi sosial.
- Memiliki sistem login kompleks.
- Memiliki database user publik.
- Memiliki payment system.
- Menjadi platform untuk banyak pengguna.
- Memiliki fitur chat real-time.
- Menjadi website komersial.
- Menyimpan data sensitif pasangan secara publik.
- Membutuhkan backend kompleks pada versi awal.

## 11. Fitur Detail

## 11.1 Opening Screen / Gift Intro

### Tujuan

Membuat pasangan merasa seperti sedang membuka hadiah digital.

### Deskripsi

Saat website pertama dibuka, pengguna melihat layar pembuka dengan background lembut, ilustrasi amplop/kotak hadiah, dan pesan singkat.

Contoh copy:

> “Aku membuat sesuatu kecil untukmu… tapi isinya semua tentang kamu.”
> 

CTA:

- **Buka Suratnya**
- **Open My Heart**
- **Mulai Cerita Kita**
- **Untukmu, Sayang**

### Komponen UI

- Background gradient light.
- Animasi floating hearts.
- Card amplop atau gift box.
- Button utama.
- Small subtitle.
- Optional music permission prompt.

### Interaksi

- Klik tombol membuka halaman utama.
- Animasi amplop terbuka.
- Setelah animasi selesai, scroll otomatis ke hero section.
- Jika musik tersedia, tampilkan prompt:
    
    > “Putar lagu kecil untuk menemani?”
    > 

### Acceptance Criteria

- Opening tampil maksimal 2 detik setelah page load.
- Tombol jelas dan mudah ditekan di mobile.
- Animasi tidak lebih dari 1.5 detik.
- Jika pengguna menolak audio, website tetap berjalan normal.
- Opening bisa dilewati.

## 11.5 Photo Memories — Polaroid Gallery

### Tujuan

Menampilkan foto-foto pasangan dalam format estetik dan romantis.

### Deskripsi

Galeri foto menggunakan gaya polaroid, scrapbook, atau grid masonry. Setiap foto dapat memiliki caption pendek.

1. **Polaroid scattered layout**

    - Ada rotasi kecil.
    - Cocok untuk kesan scrapbook.

    - Rapi, modern, dan estetik.

    - Satu foto besar per slide.
    - Cocok untuk mobile.

Rekomendasi:

- Mobile: carousel atau 2-column grid.

### Komponen UI

- Photo card.
- Caption.
- Date badge opsional.
- Heart icon.
- Lightbox modal.
- Decorative tape/sticker.

### Interaksi

- Klik foto membuka lightbox.
- Swipe foto di mobile.
- Hover desktop: foto sedikit naik dan muncul caption.
- Tap heart untuk animasi kecil.
- Optional filter:
    - Semua
    - Lucu
    - Manis
    - Favoritku
    - Kenangan

### Acceptance Criteria

- Foto loading cepat.
- Grid tidak merusak layout.
- Lightbox bisa ditutup.

- Caption tetap terbaca.

>

## 11.9 Interactive Romantic Section

### Tujuan

Memberikan pengalaman playful dan romantis, bukan hanya membaca.

### Ide Fitur Interaktif

#### A. Memory Jar

Pengguna klik jar/toples digital, lalu muncul pesan random.

Pesan contoh:

- “Aku suka saat kamu tertawa.”
- “Satu hal yang selalu aku ingat: cara kamu membuatku tenang.”
- “Kalau aku bisa mengulang satu hari, aku ingin mengulang hari saat kita tertawa bersama.”

Komponen:

- Ilustrasi jar.
- Floating notes.
- Random message modal.
- Counter jumlah pesan terbuka.

#### B. Love Quiz

Mini quiz berisi pertanyaan lucu tentang hubungan.

Contoh:

- “Menurutku, senyummu itu…”
    - A. Manis
    - B. Bikin kangen
    - C. Obat capek
    - D. Semua benar

Setelah menjawab:

> “Benar. Jawabannya selalu kamu.”
> 

#### C. Scratch Card Message

Pengguna mengusap/menggerakkan cursor untuk membuka pesan tersembunyi.

Pesan:

> “Aku sayang kamu. Selalu.”
> 

#### D. Tap the Hearts

Banyak hati kecil muncul, pengguna tap beberapa hati untuk membuka pesan.

#### E. Choose a Flower

Pengguna memilih bunga digital, lalu muncul arti bunga tersebut.

Contoh:

- Rose: “Untuk cinta yang hangat.”
- Tulip: “Untuk rasa sayang yang tumbuh pelan-pelan.”
- Daisy: “Untuk senyum yang selalu cerah.”

### Rekomendasi MVP

Gunakan 3 interaksi:

1. Memory Jar.
2. Digital Flower.
3. Scratch Card Message.

### Acceptance Criteria

- Interaksi mudah dipahami.
- Tidak memerlukan login.
- Berjalan di mobile.
- Ada feedback visual setelah klik/tap.
- Tidak menggunakan animasi berat.
- Semua interaksi memiliki fallback text.

### 13.3 Responsiveness

### 13.3 Mobile-First Responsiveness

Website ini harus dirancang dengan prinsip **mobile-first**, bukan sekadar desktop layout yang diperkecil. Target utama pengalaman adalah ketika pasangan membuka link melalui HP, sehingga semua keputusan layout, ukuran komponen, urutan konten, interaksi, dan performa harus diprioritaskan untuk layar smartphone.

Breakpoints:

- Small mobile: 320px–374px.
- Standard mobile: 375px–430px.
- Large mobile: 431px–767px.
- Tablet: 768px–1023px.
- Desktop: 1024px ke atas.

Prioritas utama mobile:

- Desain awal dibuat untuk viewport mobile terlebih dahulu.
- Desktop merupakan enhancement, bukan baseline utama.
- Semua section harus nyaman dinikmati dengan satu tangan.
- CTA utama berada di area yang mudah dijangkau ibu jari.
- Tidak ada elemen penting yang hanya bisa diakses dengan hover.
- Semua interaksi harus mendukung tap, swipe, dan scroll natural.
- Foto/video tidak overflow dan tidak memaksa pinch zoom.
- Card tidak terlalu kecil dan tetap readable di layar 320px.
- Section tidak terlalu padat agar pengalaman membaca terasa lembut.
- Animasi harus ringan agar tidak membuat HP terasa lag.
- Bottom spacing harus cukup agar tidak tertutup browser bar.

Mobile UX target:

- Pasangan bisa membuka, membaca, swipe foto, menonton video, membuka gift, dan membaca surat tanpa kebingungan.
- Semua konten romantis terasa seperti **membuka scrapbook cinta di layar HP**.
- Scroll harus terasa seperti perjalanan emosional yang pelan, manis, dan intimate.

### 13.4 Privacy

- Jangan index ke search engine jika tidak ingin publik.

- Hindari menampilkan informasi pribadi seperti alamat, nomor telepon, atau data keluarga.
- Gunakan hosting yang aman.
- Jangan commit foto/video pribadi ke repository publik jika tidak nyaman.

### 13.5 Reliability

- Website tetap berjalan jika musik gagal dimuat.
- Jika foto/video gagal, tampilkan placeholder.
- Jika JavaScript error pada fitur interaktif, konten utama tetap bisa dibaca.
- Build harus berhasil tanpa warning besar.

### 32.2 Date Counter Logic

```tsx
export function getDaysSince(dateString: string) {
  const start = new Date(dateString)
  const today = new Date()
  const diff = today.getTime() - start.getTime()
  return Math.floor(diff / (1000 * 60 * 60 * 24))
}
```

### 32.3 Reduced Motion Hook

```tsx
export function useReducedMotionPreference() {
  const [reduced, setReduced] = useState(false)

  useEffect(() => {
    const media = window.matchMedia("(prefers-reduced-motion: reduce)")
    setReduced(media.matches)

    const listener = () => setReduced(media.matches)
    media.addEventListener("change", listener)

    return () => media.removeEventListener("change", listener)
  }, [])

  return reduced
}
```
